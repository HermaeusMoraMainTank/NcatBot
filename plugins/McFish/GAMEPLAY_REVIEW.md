# McFish 玩法与经济循环评估

> 调研日期：2026-09-15
>
> 本文只提供玩法设计建议，不包含具体开发任务、代码实现或数值迁移方案。

## 1. 结论先行

当前 McFish 的问题不是“鱼种和特殊玩法太少”，而是**金币没有成为成长系统的主循环资源**。

当前工作区版本已经具备：

- 四个每日轮换鱼点、每周鱼王链和鱼王策略交互；
- 普通鱼、隐藏鱼、鱼王、鱼竿、宝藏、垃圾、碎片等多类掉落；
- 鱼竿耐久、维修、附魔、合成、等级门槛和消耗品装备；
- 动态商店库存、每日价格波动、购买/出售、出售折扣和交易诅咒；
- 个人图鉴、概率查询、鱼王时钟、GroupEconomy 钱包与账本接入。

因此，优先级不应是继续堆叠鱼种或小游戏，而应是补齐以下闭环：

```text
钓鱼获得鱼获
    -> 出售或完成订单，获得金币
    -> 支付鱼饵、维修、区域/容量、合成和服务费用
    -> 提升下一轮钓鱼效率或解锁目标
    -> 消耗更多资源，继续钓鱼
```

建议先实现一个稳定、低打扰的 NPC 经济循环，再考虑玩家市场、交易所和 PVP 社交玩法。

## 2. 调研范围与限制

本评估基于：

- 当前工作区中的 `plugins/McFish/` 与 `plugins/GroupEconomy/`；
- 当前工作区已有的 [玩法扩展提案](GAMEPLAY_PROPOSAL.md)；
- 参考插件 [NullumNomen/astrbot_plugin_fishing](https://github.com/NullumNomen/astrbot_plugin_fishing) 的 README 与公开功能说明。

参考插件 README 当前标记为暂停维护，公开说明显示其功能已经远大于一个基础钓鱼插件。本文比较的是它公开描述的系统方向，不假设所有功能都适合直接移植到 NcatBot。

## 3. 功能对比

| 维度 | 当前 McFish | 参考插件 | 判断 |
|---|---|---|---|
| 基础钓鱼 | 鱼点轮换、普通鱼、隐藏鱼、鱼王窗口和鱼王策略 | 多鱼种、多稀有度、区域与通行证 | McFish 已有较强的核心玩法，不需要从“增加鱼种”开始 |
| 成长 | 鱼竿等级、耐久、维修、附魔、合成、碎片装备 | 鱼竿/饰品精炼、锁定、道具和区域解锁 | 两者都有成长；McFish 的成长消耗偏材料，金币参与不足 |
| 鱼获处理 | 主要是卖给商店、进入个人统计或作为美西螈消耗 | 鱼塘、水族箱、批量出售、鱼类市场 | 参考插件让鱼获先成为资产，再决定出售、保存或交易 |
| 商店 | 单一商店，价格波动、库存、消耗品和鱼竿 | 普通/高级/限时多商店，复杂成本、限购和库存 | 参考方向有价值，但先做有限 NPC 订单/服务即可 |
| 玩家交易 | GroupEconomy 有转账，但 McFish 没有鱼获市场 | 鱼类、道具和大宗商品均可上架交易 | 可增加流通，但不能直接解决金币总量膨胀 |
| 大宗商品 | 没有 | 鱼干、鱼油、鱼卵，动态价格、腐败、税费和持仓上限 | 适合作为后期玩法，不适合作为第一版金币修复方案 |
| 存储压力 | 背包有鱼和物品数量，但没有鱼塘/水族箱分层 | 鱼塘容量、水族箱容量、容量升级 | “容量”是自然的金币消耗点，值得借鉴 |
| 社交 | 经济插件支持签到、送礼和钱包排行 | 偷鱼、电鱼、转账、红包、称号、成就 | 参考插件互动更强，但偷鱼/电鱼会带来冲突与并发风险 |
| 额外游戏 | 没有与钓鱼强绑定的赌博玩法 | 骰宝、命运之轮、擦弹、抽卡 | 这些可以回收金币，但会把插件变成综合赌场，不应优先加入 |

参考插件最值得借鉴的不是“功能数量”，而是它把同一份鱼获放入了多个决策点：

```text
钓到鱼 -> 暂存于鱼塘 -> 保存到水族箱 / 出售 / 上架 / 作为商品或活动材料
                       -> 容量、手续费、税费、腐败和升级形成消耗
```

## 4. 当前金币循环诊断

### 4.1 金币来源

当前主要来源包括：

- GroupEconomy 每日签到，默认 30–60 金币；
- 出售普通鱼、隐藏鱼、鱼王、宝藏、垃圾和多余鱼竿；
- 通过钓鱼获得的高价值物品出售；
- 管理员奖励和其他经济插件的外部发放。

### 4.2 金币消耗

当前明确的 McFish 消耗包括：

- 购买鱼竿、鱼、宝藏、垃圾和消耗品；
- 无鱼竿时购买应急木竿；
- 购买净化书或其他商店物品。

但这些消耗存在三个结构性问题：

1. **核心成长不消耗金币**：维修使用同名鱼竿，附魔使用附魔书，鱼竿/装备合成使用材料和碎片，长期目标完成后钱包仍会继续增长。
2. **商店支出不是稳定的服务支出**：玩家可以选择不买；而钓鱼本身不要求购买鱼饵或支付运营成本。
3. **出售是高频确定性回收**：鱼获、垃圾和多余装备最终都能变成金币，且部分成长材料不会同步消耗金币。

所以当前更接近：

```text
签到 + 钓鱼出售 -> 钱包增加
                         \-> 偶尔买东西
```

而不是：

```text
赚取金币 -> 维持钓鱼与成长 -> 解锁更高收益 -> 支付更高维护成本
```

### 4.3 不建议用“提高商品价格”直接修复

单纯提高鱼竿、消耗品或净化书价格，会让新玩家更难进入，但不会改变老玩家的资产结构；单纯降低出售价格，也会削弱钓鱼反馈，不能产生新的决策。

应该增加**玩家愿意主动购买、且与玩法直接相关的服务**，让金币消耗发生在成长和选择上。

## 5. 推荐改造方向

### P0：先补一个稳定的金币闭环

#### 5.1 鱼饵/钓鱼补给作为可选但有价值的成本

增加基础鱼饵、强化鱼饵或钓鱼补给包。建议：

- 普通鱼饵价格低、效果只影响等待或普通鱼效率；
- 特殊鱼饵继续使用现有碎片装备体系，不与基础鱼饵混为一谈；
- 可以允许无鱼饵继续钓鱼，但收益效率更低，避免金币为零的玩家被完全卡死；
- 以“每日平均钓鱼收入的一小部分”校准价格，而不是按单次鱼王收益定价。

这样金币会进入每轮钓鱼，而不是只在玩家偶尔购买装备时流出。

#### 5.2 维修改为金币 + 同名鱼竿材料

当前维修只消耗同名鱼竿。建议保留材料要求，同时加入金币维修费：

- 鱼竿等级越高，基础维修费越高；
- 耐久缺口越大，费用越高；
- 维修费设置上限，避免低耐久高等级鱼竿一次维修价格失控；
- 维修仍受现有维修次数上限约束，不要通过金币绕过所有限制。

这是最自然的金币消耗点，因为玩家已经理解“鱼竿需要维护”，不需要额外引入新的货币。

#### 5.3 合成和装备加入金币手续费

现有碎片和材料体系可以保留，金币作为加工手续费加入：

- 鱼竿合成：碎片或三根材料 + 金币；
- 永久装备：碎片 + 金币；
- 消耗品：碎片 + 少量金币；
- 高等级合成费用递增，但失败时不额外扣第二次手续费。

金币在这里不是替代碎片，而是让“资源已经足够”的老玩家仍然有持续支出。

#### 5.4 增加金币看板和经济调参依据

GroupEconomy 已经有不可变账本、`total_earned` 和 `total_spent`。建议 McFish 后续只增加统计视图，不另建一套钱包：

- 统计签到、钓鱼出售、商店购买、维修、合成、净化等 reason；
- 按日/周显示全体金币发行量、回收量和净变化；
- 观察余额中位数、前 10% 余额占比和长期不消费玩家比例；
- 先运行一周数据，再调整出售倍率、维修费和补给价格。

没有这张看板时，任何“通胀修复”都只能凭感觉调数值。

### P1：让鱼获产生更多选择

#### 5.5 NPC 鱼获订单，替代一开始就做玩家市场

参考插件的市场很完整，但 McFish 更适合先加入有限的 NPC 订单：

- 每日刷新 3–5 个订单，指定鱼种、数量或鱼点；
- 订单有截止时间和有限完成次数；
- 奖励以金币、碎片、图鉴印章或称号为主，不全部奖励金币；
- 高价值订单要求玩家保留稀有鱼，而不是无脑出售全部鱼获；
- 可加入少量接单/刷新手续费，形成金币回收。

订单能增加“今天钓什么”的决策，开发复杂度和社交风险都低于自由市场。

#### 5.6 鱼获品质、尺寸或收藏保留

当前普通鱼主要按名称堆叠出售，图鉴记录捕获但不改变鱼获处理。建议先只给少数鱼种增加品质或尺寸：

- 普通鱼：直接出售或用于订单；
- 高品质/大体型鱼：更高售价，也可作为图鉴收藏；
- 首次捕获、最大尺寸、鱼王长度继续进入图鉴；
- “锁定/保留”后批量出售不能误卖。

这能借鉴参考插件的鱼塘/水族箱决策，但不必马上引入完整存储系统。

#### 5.7 容量与安全存储

如果后续增加鱼获品质和订单，建议再引入两个容量：

- 鱼塘：普通临时存储，满后停止自动积累或降低效率；
- 水族箱/仓库：付费升级的安全存储，保存收藏鱼，不参与被动清理。

容量升级是长期、可预测的金币消耗，也能给富余金币提供用途。必须提供容量提示、批量出售和保护锁，避免容量变成强制惩罚。

### P2：经济成熟后再考虑

#### 5.8 玩家市场或大宗商品交易所

参考插件的鱼类市场和鱼干/鱼油/鱼卵交易所能提供更强的流通性，但应满足以下前提后再做：

- 钱包转账和账本 reason 已经稳定；
- 所有上架、购买、下架、超时和退款均可幂等；
- 交易手续费、成交税和容量上限先写入设计；
- 价格波动不能产生无风险套利；
- 管理员能查看异常交易和玩家资产变化。

建议先做“鱼获上架 + 固定手续费 + 统一回收税”，暂时不做自由定价的大宗商品、做空、复杂技术指标和腐败系统。

#### 5.9 社交竞争玩法

排行榜、红包和转账主要是金币流通，不会自动减少全局金币；它们不能替代金币回收机制。

偷鱼、电鱼虽然能制造互动和损失，但会带来：

- 新玩家被反复针对；
- 离线玩家资产损失；
- 钓鱼后台结算与偷取并发冲突；
- 争议处理、保护道具和管理员介入成本。

如果以后加入，建议默认关闭或按群开启，先做保护期、每日次数、损失上限和日志查询；不应作为第一阶段的通胀修复手段。

#### 5.10 骰宝、命运之轮、抽卡等玩法

参考插件的骰宝、命运之轮和抽卡确实能制造金币支出，但它们会把经济问题转化为概率游戏问题。除非明确需要综合娱乐插件，否则不建议加入 McFish 核心。

如确实要做，必须满足：

- 每个玩法单独限次、限额；
- 期望回报低于 1，并公开赔率；
- 失败、超时和并发结算都能恢复；
- 不把签到金币设计成唯一赌资来源。

## 6. 建议的分阶段顺序

### 第一阶段：修复金币循环

1. 增加金币流水分类和经济看板；
2. 维修加入金币费用；
3. 合成/装备加入金币手续费；
4. 增加基础钓鱼补给或鱼饵成本；
5. 统计一周的金币流入、流出和余额分布。

### 第二阶段：增加鱼获决策

1. NPC 鱼获订单；
2. 品质/尺寸/收藏锁定；
3. 鱼塘或仓库容量；
4. 容量升级和订单刷新等稳定服务型消耗。

### 第三阶段：扩展社交经济

1. 受控的鱼获市场；
2. 成交手续费与税收；
3. 可选的红包/转账联动；
4. 最后评估偷鱼、电鱼和综合小游戏。

## 7. 不建议现在做的事情

- 只增加鱼种、鱼竿或稀有度，不增加鱼获用途和金币消耗；
- 直接把签到奖励降到很低，靠压缩新玩家收入解决通胀；
- 直接把出售倍率砍半，导致玩家觉得钓鱼没有反馈；
- 一次性照搬参考插件的交易所、市场、抽卡、骰宝和 PVP；
- 用偷鱼、电鱼直接从玩家钱包扣除金币；
- 让每次普通钓鱼都需要多轮手动回复；
- 在没有流水统计的情况下同时改动签到、出售、商店和鱼王价格。

## 8. 验收指标建议

后续实现前，建议先约定以下指标，而不是只看“命令数量”：

| 指标 | 目标方向 |
|---|---|
| 每周全体金币净发行量 | 接近可接受范围，不长期单向上升 |
| 活跃玩家 7 日收入/支出比 | 不应长期远高于 1 |
| 有余额但一周无消费的玩家比例 | 随服务型消耗下降 |
| 新玩家达到第一根进阶鱼竿的时间 | 可预测，不因新增费用变成硬门槛 |
| 普通鱼获的出售率 | 不能接近 100%，应有订单/收藏/加工选择 |
| 维修、补给、合成费用占比 | 足以形成回收，但不超过日常收入承受范围 |
| 玩家对鱼王和订单的参与率 | 判断玩法是否真的增加决策，而不是增加阅读量 |

## 9. 最终建议

推荐采用以下最小闭环：

```text
钓鱼 -> 鱼获出售/订单 -> 金币
金币 -> 鱼饵/维修/合成手续费/容量升级
成长 -> 更高鱼点、鱼王和订单效率
高价值鱼获 -> 收藏、订单或受控市场，而不是只能出售
```

这条路线能直接回应“金币只增不减”，同时保留当前 McFish 已经完成的鱼王、装备、碎片和图鉴设计。参考插件的交易所、PVP 和赌博玩法可以作为以后独立模块评估，不应成为这次改造的起点。
