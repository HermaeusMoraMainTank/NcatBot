# Robbery

移植自 `FloatTech/ZeroBot-Plugin` 的群友钱包打劫功能。

## 命令

- `打劫 @用户`
- `打劫 QQ号`
- `打劫帮助`：在群里查看玩法说明

发起者和目标余额都至少为 1000 才能发起打劫；成功率为 40%；失败时随机赔偿目标 1 到本次潜在抢劫金额 50% 之间的金币；成功获得对方 0% 到 2.5% 的财产，再加上按目标余额档位浮动的基础值，上限为 `max(10000, 对方余额的 10%)`。

单次收益还会被发起者自身余额限制：最多抢到发起者余额的 1 倍，余额越少抢到的钱越少。因此 1000 金币的人仍可以打劫千万富翁，但最多只能拿走 1000 金币，成功消息会附带「（受身家限制）」。账号 `273421673`、`635773721` 不受此限制。

默认情况下账号 `273421673`、`635773721` 被抢时成功率固定为 0，必定打劫失败并赔偿对方；但这两个账号互相打劫时按正常概率结算。可通过 `guaranteed_failure_exempt_users` 临时豁免其中某个账号，使其重新可以被抢成功。每日可打劫或被打劫一次，失败不计入次数。

基础值档位：

| 目标余额 | 基础值 |
|---------|--------|
| 0 ~ 1 万 | 500 |
| 1 万 ~ 10 万 | 1000 |
| 10 万 ~ 100 万 | 5000 |
| 100 万以上 | 20000 |

可调配置：

- `stolen_balance_ratio`：普通目标的单次可抢余额比例，默认 `0.025`；
- `base_stolen_tiers`：基础值档位列表，每项为 `{min_balance, base}`，按 `min_balance` 从高到低匹配；
- `max_stolen`：金额上限的保底值，默认 `10000`；
- `max_stolen_ratio`：金额上限随目标余额放大的比例，默认为 `0.10`，实际上限取它与 `max_stolen` 的较大值；
- `max_loot_balance_ratio`：单次收益最多为发起者余额的多少倍，默认 `1.0`，设为 `0` 关闭限制；
- `loot_cap_bypass_users`：不受身家限制的账号列表，默认包含 `273421673`、`635773721`；
- `guaranteed_failure_users`：被抢时成功率固定为 0 的账号列表，默认包含 `273421673`、`635773721`；名单内账号互相打劫时不受此限制；
- `guaranteed_failure_exempt_users`：临时解除被抢保护的账号列表，默认空；名单内账号即使也在 `guaranteed_failure_users` 中，被抢时仍按正常概率结算。

## 后台测试账号配置

插件支持通过 `test_user_profiles` 配置仅后台生效的测试账号参数。测试账号配置不会出现在普通用户消息中：

- `victim_success_rate`：目标被成功抢劫的概率；
- `stolen_balance_ratio`：按目标余额计算的可抢金额比例，基础值仍按档位计算；
- `loss_stolen_ratio`：目标实际损失占潜在抢劫金额的比例；
- `robbery_failure_rate`：该账号发起抢劫时的失败率。

默认测试配置为账号 `10123121`：被抢成功率 60%、金额比例 10%（不受普通用户 2.5% 的限制）、实际损失比例 10%、抢劫失败率 75%，并通过 `is_test_account` 标记。未命中测试账号时，使用本页前述生产默认规则。
