# HealthDiet 安全规则

插件启动时会审计健康数据库，并将明显异常的数据永久登记到 `permanent_bans` 表。封禁用户的健康命令会在档案解析、饮食解析和评估分析之前被拦截，因此不会再次调用 AI。

当前硬规则包括：

- 档案 BMI 达到 80 或更高；
- 单项食物热量达到 10,000 kcal 或更高；
- 单项食物重量达到 50,000 g 或更高；
- 个、只、块、杯、听、碗、份、包、瓶、斤、条等计数单位的单项数量达到 100 或更高；
- 单日记录热量达到 50,000 kcal 或更高；
- 饮食原文包含明确的危险物品、虚构人物/生物或明显玩梗内容。

封禁只停止健康功能，不删除历史档案和饮食记录。管理员 `273421673` 可使用 `健康封禁 QQ号 [原因]`、`健康解禁 QQ号`，也可以使用 `健康封禁 @成员 [原因]`、`健康解禁 @成员` 管理成员。

## 饮食解析速度与兜底

普通饮食记录仍通过共享的 DeepSeek 官方接口估算；健康评估的详细分析使用独立请求。

文本 AI 调用默认不注入 `max_tokens`，并将客户端与单次请求的 `timeout` 设为 `None`，不人为限制生成长度或网络等待时间；需要限制时，调用方仍可显式传入参数。

饮食明细完全由 AI 解析。若第一次返回空明细、格式错误或项目无效，插件会使用复核提示再次读取完整原文，要求拆分蛋白粉、牛奶、包装食品、饮料和泡腾片等每个项目，并按包装标签估算营养值；不使用食物营养正则作为兜底。

未写明餐次时，插件按配置时区的当前时间推断早餐、午餐、晚餐或加餐。评估今天时，会按当前时段的阶段参考摄入判断；例如下午尚未到晚餐，不会把未发生的晚餐直接算成严重全天热量缺口。昨天或更早日期仍按完整一天评估。

管理员 `273421673` 可使用 `健康禁用` 和不带参数的 `健康解禁` 控制整个健康功能。开关状态保存到插件 `data.json`，禁用期间普通健康指令不会调用 AI 或写入数据库；管理员仍可使用解禁指令。

饮食记录默认写入今天，也可以使用 `健康记录 昨天 早餐吃了两个鸡蛋` 将记录写入昨天；日期词后需要继续提供饮食描述。
