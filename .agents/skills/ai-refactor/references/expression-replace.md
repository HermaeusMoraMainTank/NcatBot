# Phase 3 · `:贴纸名:` 替换规则

> 挂在专家生成文案 → 真正 `post_group_msg` 之前（可改造现有 `send_typing_response` 流水线）。

---

## 1. 语法

- 形式：`:贴纸名:`（全角冒号不算；必须英文冒号）
- 贴纸名：与目录扫描名完全一致（大小写敏感，建议全用中文短名）
- 例：`好的我会去的 :坏笑:`

非法 / 未知名：默认 **删除未知标记并打 warn**，避免露出 `:xxx:`。

---

## 2. 数量限制

1. 每轮回复最多生效 `max_per_message`（默认 **1**）张贴纸。  
2. 若模型输出多个：只保留 **第一个** 有效命中，其余标记删除。  
3. 无命中则纯文本发送，行为与现在一致。

---

## 3. 与拆句发送的关系（已确认）

现状：`send_typing_response` 按 `。！？` 拆成多条群消息。

**贴纸不得与文字并在同一条消息内。**

| 步骤 | 行为 |
|------|------|
| 1 | 从整段 `content` 抽出最多 N 个有效 `:名:`，并从正文删除这些标记 |
| 2 | 正文按现有规则拆句，只发 `PlainText` / `At` |
| 3 | 正文全部发完后，再各发一条 **仅含** `Image` 的消息 |

若抽掉标记后某句变空 → 不发该空句。  
若只有贴纸、无文字 → 只发图片消息。

发送顺序：

```text
文字句1 → 文字句2 → … → Image(贴纸1) → …
```

配置键 `max_per_message` 语义为「每轮回复最多贴纸张数」（每张单独一条）。

---

## 4. 变体

`catalog[name]` 为多 Path 时：`random.choice`；多张时可避开连抽同一文件（可选）。

---

## 5. 失败降级

| 情况 | 行为 |
|------|------|
| 文件缺失 | 不发图；日志 error；文字照常发 |
| 路径不可读 | 同上 |
| `expression.enabled=false` | 剥离所有 `:…:`，不发图 |
