# FakeAi（蓝晴）从输入到输出：现状架构

> 目的：把当前真实链路摊开，定位「为什么还是伪人」。
> 代码基准：2026-11-12，`plugins/FakeAi/FakeAi.py` 约 4400 行。

## 0. 一张总览

```text
群里一条消息
  → 入口过滤（插件代发 / 群白名单 / 管理命令 / 冻结）
  → 入账（ReplyCache + 群消息 DB + 摘要缓冲）
  → 触发判定（状态机 + 触发档位 + 随机/退避 + 冷却 + 限额）
  → 阅读延迟（1~3 秒，同人补话再多等）
  → 上下文组装（人设 + 最近 20 条 + 记忆胶囊 + 印象 + 上次锚点 + 群语感样本）
  → 生成
       ├─ 普通闲聊：Planner（一句方向）→ Replyer（1~2 条）
       └─ 功能/识图：Agent（工具循环，最多 8 轮）
  → 后处理（问号替换 / 长句拆两条 / 按情绪补表情）
  → 发送（文字分片 + 打字间隔 + 表情/语音/图/拍一拍/点赞）
  → 回写（ReplyCache、auto_remember、trace、统计）
  → 定时任务（摘要、印象、记忆巩固、清理）
```

## 1. 入口层：哪些消息根本不会进 AI

`FakeAi.py:2079` `handle_fake_ai()`

按顺序过滤：

1. 插件代发的合成消息（`synthetic`）直接跳过；
2. `_is_from_excluded_plugin()` 排除指定插件的消息；
3. 用事件 `self_id` 校准 `BOT_QQ`，避免配置里的 QQ 过时识别不到 @；
4. `蓝晴启用/关闭`：只允许 `273421673` 改本群开关；
5. 群白名单 / 黑名单判断（`_is_fakeai_group_allowed`）；
6. 管理员回复「撤回」不触发 AI；
7. `蓝晴说话`：测试指令，强制走一次 `answer_ai`；
8. `说 xxx`：MiMo TTS，直接发语音；
9. `查询余额`、`蓝晴印象`、`蓝晴知识库`、`蓝晴好感度排行`、`测试`（识图测试）：各自走专用处理函数；
10. 冻结用户：除好感度外全部跳过。

**特点**：管理/功能命令是硬编码在入口里的，和 AI 对话混在同一个 handler。功能越多，入口越像命令分发器。

## 2. 入账层：消息怎么被记住

`FakeAi.py:2162` `_build_message_content()` + `:2269` 起

- 把 `MessageArray` 转成可序列化内容；
- 收集图片/视频 URL；agent 模式下把图片标成 `[图片#id]`，不在此处描述；
- 写进 `ReplyCache`（每群最近 60 条，`ReplyCache` 在 `:337`）；
- 写进 `_message_buffer`，供 10 分钟一次的摘要任务；
- 写进 SQLite `group_messages`，供 `group_history` 工具和语料脚本翻旧账。

**特点**：所有消息都进同一个平铺时间线，没有「回复关系 / 话题线程」结构。模型看到的是 `[时间] 昵称: 内容`，需要自己推断谁在跟谁说话。

## 3. 触发层：什么时候开口

`FakeAi.py:2303` 起 + `interaction/state_machine.py`

### 3.1 三个状态

- `NOT_PRESENT`：平时潜水；
- `SUMMONED`：被 @ / 叫名字；
- `FAMILIAR`：刚被叫过，对话窗口内继续接话（`dialog_window_sec`，默认 180 秒，最多 `dialog_max_rounds` 轮）。

`determine()` 的判定顺序：

1. 被 @、叫名字、或最近有人叫过 → `SUMMONED`；
2. 静默期（被要求闭嘴）→ `NOT_PRESENT`；
3. 对话窗口未过期 → `FAMILIAR`；
4. 否则 `NOT_PRESENT`。

### 3.2 不在场时的四档

`trigger_tier`：

1. 只回 @ / 叫名字；
2. 再加关键词；
3. 再加随机概率（`random_percent`，默认 8%）；
4. 全部回。

随机触发连续沉默会指数退避（15s → 300s），避免每条都掷骰子。

### 3.3 硬闸门

按顺序：

- 空召唤（只叫了名字没内容）不回；
- 单人限额：同一群、同一人 3 次/小时、10 次/天（`273421673` 豁免）；
- `SUMMONED`：用户 CD + 群 CD；
- 同群生成中：`_inflight_groups` 互斥；
- 冻结用户；
- `FAMILIAR`：再占群 CD；
- 群整体额度：10 分钟 3 条 / 1 小时 15 条；
- 阅读延迟：主动 0.3~0.9s，普通 0.6~1.4s，同人补话 1.6~2.6s。

**特点**：这是一套**规则状态机**，不是语义判断。它只能判断「有没有人叫 / 时间过没过 / 随机中没中」，不能判断「这句话值不值得接、现在接会不会打断别人」。

## 4. 上下文层：模型到底看到了什么

`answer_ai()` `FakeAi.py:3975`

### 4.1 system

- 人设 YAML 的 `system`（当前蓝晴约 1.1k 字，只留身份、关系、参与、说话、示例、工具）；
- 再加 `SYSTEM_COMMON_RULES`（反 AI 味、安全、工作方式）。

### 4.2 user

- `{history_new}`：最近 `history_count` 条（默认 20），可读格式；
- `{history_last}`：最后一条；
- `{long_term_memory}`：记忆胶囊，只给存在性，不给细节；
- `{user_impressions}`：最近 8 条里出现过的群友，最多 4 人的印象；
- `{user_anchor}`：当前说话人 1 小时以前的一条真实发言；
- `{related_memories}`：agent 模式只写「用 memory_query 查」；直出模式会预取 3 条；
- `{related_knowledge}`：已下线；
- `{style_corpus}`：从本群真实消息里按当前话题挑 4 条；
- 动态块：本次唤醒、群脉冲、当前时间、表情包清单/节奏、技能提示。

### 4.3 上下文压缩

`_compress_reply_cache()`：超过 30 条时，把前段压成两句摘要，保留最近 20 条。

**特点**：
- 记忆是「胶囊 + 印象 + 一条锚点 + 3 条检索」，不是完整的关系记忆；
- 没有话题线程，模型自己推断；
- 表情清单会以工具说明的形式进入 agent 上下文，容易把模型拉回「agent 语域」。

## 5. 生成层：两条路

### 5.1 普通闲聊：Planner → Replyer

`FakeAi.py:4199` 起，`_direct_chat()` `:512`

1. **Planner** `_plan_reply()` `:491`
   - 输入：同一份上下文（历史、记忆、印象、语感样本）；
   - 输出两行：`方向：...` / `表情：happy|sad|angry|confused|daily|无`；
   - `max_tokens=80`，失败就跳过。
2. **Replyer** `_direct_chat()`
   - system = 人设去掉「【工具】」段 + 一段「直接说话」规则；
   - user = 上下文 + 相关记忆 + 时间 + `【回复方向】`；
   - 输出 1~2 条，每条一行；
   - `max_tokens=300`，temperature 0.95；
   - 过滤括号独白、Markdown、工具元话（「表情包库存」等）。

选择直出的条件（`_direct_chat_ok`）：
- `direct_chat_enabled` 打开；
- 触发类型是 active/passive/event；
- 没有图片 base64；
- 消息里没有明确的功能请求（占卜、点歌、签到、钓鱼、图库、算数、查物价、识图等）。

### 5.2 功能/识图：Agent 工具循环

`agent.py:1272` `run_agent()`

- 最多 `agent_max_rounds`（默认 8）轮；
- 工具集：`send_message`、`send_sticker`、`sticker_search`、`send_meme`、`send_voice`、`send_image`、`send_poke`、`react`、`memory_query`、`memory_append`、`web_search`、`list_skills`、`invoke_skill`、`finish` 等；
- 模型必须调用 `send_message` 才算说话，正文只是思考；
- `LIGHT_TOOLS` 用于 passive 轮，减少工具选择；
- `skill_bridge` 接 SkillHub，插件结果可以直接发图。

**特点**：这条路是「agent」，语域天然偏助手/执行者。功能请求走它是合理的，但以前所有闲聊也走它，这是伪人感的主要来源之一。

## 6. 后处理层：发出去之前还会被改

`_shape_reply()` `:323`：

- 最近 20 条里已经出现过纯「？」，这次的「？」会换成「啥 / 没懂 / 你说啥 / 什么意思 / 啊」；
- 单条 10~30 字、带逗号或空格时，30% 概率拆成两条；
- 不做重复末字（之前会产出「行行」「用用」，已删）。

`_auto_pick_sticker()` `:3859`：

- 没有表情动作时，按 `sticker_auto_rate`（25%）决定补不补；
- 先用 Planner 给的 `mood_hint`，否则从回复文本判断情绪桶；
- 本地图库按 `search(回复文本, mood)` 找匹配，找不到才 `pick_any()`；
- 梗鲸图库用回复正文取图。

发送 `send_agent_result()` `:2793`：

- 单轮最多 5 条；
- 文字按 600 字切片；
- 8 秒内重复话跳过；
- 每群 12 条/分钟、120 条/小时；
- `apply_tone()` 去句号、少量「吧/的/犹豫」；
- 条与条之间按字数 sleep（0.5~4.5 秒）；
- 最后把本轮文字合并写回 `ReplyCache`。

## 7. 回写与定时任务

- `maybe_auto_remember()`：命中短语时写主动记忆；
- `trace.record_turn()`：每轮留档（system/user/actions/usage），供后台和体检脚本；
- `AiStatsRecorder`：token 统计；
- 定时：5 分钟持久化缓存、10 分钟摘要、15 分钟用户印象、60 分钟记忆巩固、24 小时清理、60 秒扫贴纸、30 秒发定时消息。

## 8. 为什么现在还是「伪人」

按影响从大到小：

### 8.1 决定「要不要说」的是规则，不是理解

状态机只看 @、名字、窗口、随机数。它不知道：
- 群里是不是在聊一个严肃话题；
- 这句话是不是在跟别人说；
- 现在插话会不会打断；
- 这个人是不是已经连续 @ 了很多次（只有次数限额，没有语义厌烦）。

所以会出现「该安静时接话、该接话时沉默、被同一个人牵着聊」的感觉。

### 8.2 Planner 只定「怎么说」，不定「说不说」

Planner 的输入是上下文，输出是方向；它没有「停止 / 等待 / 只看不说话」的选项。决定权仍在状态机。这是和 MaiBot 最大的结构差异：MaiBot 的 Planner 是决策者，Replyer 只是执行者。

### 8.3 没有消息防抖 / 合并

同一个人连发 3 条，系统会按 3 条消息分别判断；虽然有阅读延迟和 inflight 互斥，但没有「等他说完再一起看」。真人会等对方把话说完。

### 8.4 记忆是「检索片段」，不是「关系」

- 印象是静态标签；
- 锚点只有一条；
- 直出预取 3 条记忆，但模型不一定会用；
- 好感度只展示，不影响语气。

所以它记得「你毕设卡住」，但不会因为跟你熟而换一种说法。

### 8.5 人格仍是「规则 + 示例」

人设已经很短，但仍是「不要这样、要那样」的规则集合；语感样本是外部补丁。模型没有稳定的「这个人会怎么想」的内部模型。

### 8.6 Agent 回退会把语域拉回去

只要消息里出现「图、查、算、插件、技能」等词，就会切回工具 agent；agent 的提示词和工具协议会让回复变回「助手腔」。直出和 agent 之间的语域不连续。

### 8.7 模型本身

`deepseek-v4.1-flash` 便宜、工具调用稳定，但角色扮演的细腻度不如更大的模型。同一套 prompt，换模型会有明显差异。

### 8.8 后处理是「补丁」

问号替换、拆句、表情匹配都是事后规则，能减少明显问题，但不能让一句话变得「有生活感」。真正的人味来自「说了什么、为什么现在说」，不是句尾加个「吧」。

## 9. 和 MaiBot 的对应关系

| 层 | MaiBot | 蓝晴现在 |
|---|---|---|
| 何时说 | Planner + 巡检 + 防抖 + 能量 | 规则状态机 + 随机 + 限额 |
| 说什么方向 | Planner 输出发言指导 | Planner 输出一句方向（不决定说不说） |
| 怎么说 | Replyer 极简 prompt | Replyer 直出（已对齐） |
| 语料 | 表达学习 + 黑话学习 | 本群 style_corpus（手动刷新） |
| 记忆 | A_Memorix + 人格画像 | 胶囊 + 印象 + 锚点 + 3 条检索 |
| 表情 | 回复补充器按情绪/扩展编排 | mood_hint + 本地图库搜索 |
| 节奏 | debounce / wait / 能量 | 阅读延迟 + 随机退避 |

## 10. 如果继续改，优先级

1. **让 Planner 拥有「不说 / 等一等」的权力**：输出 `决策：说/不说/等 N 秒`，状态机只做硬闸门。这是最接近 MaiBot 的一步。
2. **消息防抖**：同一人 1.5 秒内连发，合并成一批再判断。
3. **关系语气**：把好感度/关系标签变成一句「跟这个人说话的语气」，而不是只展示。
4. **表达/黑话自动更新**：style_corpus 定时重建 + 人工审核。
5. **模型 A/B**：同一批上下文，比较 `ocgo_ds_flash` / `ocgo_ds_pro` / `deepseek-flash` 的盲评分数。
