# Phase 1 · 交互行为预览（请确认）

> PREVIEW 风格。确认本文件后，Phase 1 文档关单；**实现仍需另行下令**。  
> 人设：蓝晴。状态机 + 同模型短分析员；好感闸门仍在。

---

### 功能 1：被呼唤（SUMMONED）

被 @ 或点名「蓝晴」时，倾向认真接话；空艾特可无视。

**触发方式**：`@蓝晴` / 消息含「蓝晴」且非命令

**对话流**：
```text
用户A: @蓝晴 明天演唱会去吗
（状态→SUMMONED → 分析员 should_reply=true → 好感过 → 专家）
蓝晴: 去啊，你出票还是我出

用户B: @蓝晴
（无正文 → 分析员或规则强制 false）
蓝晴: （不回复）
```

---

### 功能 2：命令不被聊天吞掉

查询类指令优先，不消耗「闲聊回复」。

**触发方式**：`蓝晴印象` 等

**对话流**：
```text
用户A: 蓝晴印象
蓝晴: （发出印象卡片，不经闲聊人设长文）

用户A: 蓝晴好感度排行
蓝晴: （排行图）
```

---

### 功能 3：混脸熟（FAMILIAR）—— 可插可不插

复读/热闹时分析员偏严；好玩才接，不尬蹭。

**触发方式**：短时同文复读达标

**对话流**：
```text
用户A: 确实
用户B: 确实
用户C: 确实
（状态→FAMILIAR → 分析员）
  情况A should_reply=false → 蓝晴安静
  情况B should_reply=true，策略「轻轻补一句」
蓝晴: 你们这是签订契约了吗
（→OBSERVATION，一段时间不再因热闹触发）
```

---

### 功能 4：观测期不抢话

刚回过话进入观测；路人续聊不插，被再叫则打断。

**触发方式**：回复后的 `observation_sec` 内

**对话流**：
```text
用户A: 蓝晴 今晚吃什么
蓝晴: 火锅。我请空调你请胃

用户B: 那去哪家
（观测中，非唤醒 → 不回复，但消息入账）

用户A: 蓝晴 你定
（唤醒打断观测 → SUMMONED → 回复）
蓝晴: 就门口那家，六点半见
```

---

### 功能 5：低好感闸门

分析员说回，好感仍可挡。

**触发方式**：主动唤醒 + 好感过低

**对话流**：
```text
（用户Z 好感很低）
用户Z: 蓝晴出来
（SUMMONED → 分析员 true → 好感闸门 false）
蓝晴: （不回复 / 或极冷淡——以实现时好感模块规则为准）
```

---

### 功能 6：取消裸 8%（终态体验）

普通单句闲聊不再「抽卡冒泡」。

**触发方式**：无唤醒、无复读/密集

**对话流**：
```text
用户A: 我下班了
用户B: 嗯
（NOT_PRESENT，分析员不调用）
蓝晴: （不回复）
```

过渡期：仅当分析员不可用且已进入 `FAMILIAR` 时，才可能以很低概率 fallback（见 `fallback-strategy.md`）。
