# 蓝晴「不像人」诊断与改造方向（调研文档）

> 状态：调研与方案，不含实现。
> 日期：2026-11-08
> 适用：`plugins/FakeAi` 的蓝晴人设与回复链路。

## 0. 一句话结论

蓝晴现在不像人，不是"人设写得不够多"，而是**人设写得太满、太负向，且缺少真实语料与记忆支撑**：模型被 4k 字规则和一堆"不许"夹住，只能挑最安全的答案——`？`、`典`、`草`；同时 96% 的回复只有一条气泡，不接具体的人和事，所以每句话都像可替换的模板。

## 1. 先看数据：蓝晴最近的群聊表现

统计 `data/FakeAi/traces/` 全部留档（约 14 天，772 个有文字的轮次、804 条消息）：

| 指标 | 数值 | 说明 |
|---|---:|---|
| 回复 `？` 的次数 | 111（13.8%） | 单条回复里出现频率最高，是"人格口头禅"级别的固定动作 |
| `?`（半角） | 6 | 同上 |
| ≤2 个字的回复 | 172 / 804（21%） | 大量单字/符号 |
| 一条气泡就说完的轮次 | 740 / 772（96%） | 人设要求"想说的多分 2~3 条"，实际几乎不执行 |
| 超过 8 个字的回复 | 247 / 804（31%） | 具体内容偏少，多数是短反应 |
| 冷场主动消息 | 16 条"有人吗/有人在吗/有人醒着吗" | 已在 2026-11-07 删除该功能 |

这说明问题不在"话太长"（蓝晴已经很短），而在：

1. **回复形态单一**：永远是"一条 + 极短"，没有真人那种"先发一句、补一句、再补个表情"的节奏。
2. **反应动作单一**：`？` 占了近七分之一，像固定的演出动作，不像临场反应。
3. **缺少具体性**：很少提具体的人、具体的事、群里的旧梗；把发言人名字换掉，句子依然成立——这就是"伪人感"的来源。

## 2. 为什么人设写得越细，反而越像机器人

### 2.1 负向规则过载

当前 `lanqing_agent.yml` 的 system 约 3980 字，其中"不许"10 次、"不要"11 次、"别"24 次、"←"失败示例 7 处。再叠加 `SYSTEM_COMMON_RULES` 的"反 AI 味"清单，模型每轮都在做**避雷**，而不是**表达**。

避雷型提示词的副作用是：模型会收敛到"最不容易犯错的输出"。对蓝晴，这个最安全输出恰好就是 `？`。

### 2.2 长 system prompt 的注意力衰减

论文 *Measuring and Controlling Instruction (In)Stability in Language Model Dialogs*（COLM 2024）用双机器人自聊测试发现：流行模型在 8 轮内就会出现明显的 instruction drift，越靠后的对话越不遵守 system prompt。蓝晴的上下文里，system 5~6k 字、user 段 1.5k 字，到第 10 轮以后，人设的实际权重会被聊天内容稀释。

**方向不是继续加规则，而是把规则压短、把"人"放进上下文里。**

- 论文：https://arxiv.org/abs/2402.10962

### 2.3 "定义反面"不等于"定义正面"

现在的人设大量使用"别说 X，说 Y"。但示例里的 Y 是我们**编的**，不是这个群真实会说的话。模型学到的是"要短、要敷衍、要反问"，学不到"蓝晴会怎么接这个具体话题"。

参考 MaiBot 文档对人格配置的说明：`personality` 写 1~2 句就够，**太长反而稀释效果**；真正影响说话方式的是 `reply_style` 和从群里学到的表达。

- MaiBot Bot 配置文档：https://docs.maibot.chat/manual/configuration/bot-config

### 2.4 身份提示与工具协议互相打架

人设前半段说"你是群里一个普通群友"，后半段有 20 多条工具协议、硬性规则、技能调用要求。模型会同时收到两种身份信号："普通群友"和"要正确调用工具的 agent"。后者更具体、更可执行，于是输出会向"助手/客服"的语域漂移：解释清楚、有求必应、句式完整。

### 2.5 缺少"生活状态"和"关系记忆"的动态输入

人设里的"最近的生活"是静态清单（毕设、FF14、减肥），每轮原样注入。真人聊天时会带出**今天**的状态：刚下课、外卖还没到、队友又演了。没有"今日状态"这种短动态，生活设定就只是背景板，不会被说出来。

### 2.6 采样与模型

`deepseek-flash` 是低成本模型，角色扮演的稳定性弱于更大的模型；如果 temperature 偏低，输出会更保守、更像模板。这一项不是根因，但会放大上面所有问题。

## 3. 别人的机器人怎么做到像人

### 3.1 MaiBot（麦麦）——目前最完整的"像人"参考

仓库：https://github.com/MaiM-with-u/MaiBot
文档：https://docs.maibot.chat/

它的设计原则写得很直接："最像而不是好"（more lifelike, not merely better）。可借鉴的机制：

| 机制 | 做法 | 对我们的启发 |
|---|---|---|
| 三段式人设 | `personality`（是谁）/ `behavior_style`（什么时候参与）/ `reply_style`（怎么说话），每段 1~2 句 | 人设不是越长越好；拆成三块，短而准 |
| 规划与回复分离 | Planner 判断"要不要说、说什么方向"，Replyer 只负责生成 | 我们已经把"回不回"交给状态机，但"说什么方向"还没有独立决策 |
| 发言频率 | `talk_value` 0~1，可按群、按时段配置 | 用连续频率而不是固定 8% 随机 |
| 消息防抖 | natural 档：安静 2 秒、活跃 5 秒；同一人续发 2 秒、换人 0.5 秒 | 真人会等对方说完；我们现在是一有触发就立刻生成 |
| 不回复退避 | 连续决定不回复后，下次检查先等 15 秒，上限 300 秒 | 减少"每条都抢"的机械感 |
| 表达学习 | 从群聊里学习表达方式，写入前先让 AI 审核 | 语料应该来自本群，而不是人设里的编造句 |
| 黑话学习 | 单独学习群内黑话/梗，可共享给多个群 | 蓝晴现在对新梗几乎无感 |
| 回复后处理 | 中文错别字、回复分割、表情包替换 | 我们已有 tone 后处理，但没有"故意打错字"和"分条" |
| 长期记忆 | A_Memorix 记忆引擎 + 人格画像 | 我们已有记忆表，但**没有把记忆用进每句话** |
| 注意力漂移（实验） | 更容易被新话题/梗吸引，再拉回上下文 | 可解释"真人会突然岔开话题" |

MaiBot 的 Planner prompt 也值得看：它先分析局面、再决定用哪个工具、再给 Replyer 一段"回复方向指引"（`reply_reference`），而不是让一个模型同时想和说。

- 中文 prompt 目录：https://github.com/MaiM-with-u/MaiBot/tree/main/prompts/zh-CN

> 许可：GPL-3.0。只借鉴设计，不复制代码。

### 3.2 Pallas-Bot（牛牛）——"语料先行"的另一种答案

仓库：https://github.com/PallasBot/Pallas-Bot

牛牛的核心不是提示词，而是**群友自己的语料**：群友说什么她就说什么，V4 接上 LLM 之后仍然把"复读"放在前面，模型只负责"轻轻托一把"。

这给我们一个很重要的反向参照：**人格的第一来源是群体语料，不是作者写的人设**。蓝晴现在的语感全部来自 `lanqing_agent.yml` 的示例，所以听起来像"作者想象中的女大学生"，而不是"这个群里的人"。

> 许可：AGPL-3.0。

### 3.3 Angel 三件套——"什么时候说"与"记得什么"

- Angel Heart（交互状态机）：https://github.com/kawayiYokami/astrbot_plugin_angel_heart
  - 离场 / 在场两态；点名与普通消息分开等待；同一会话单飞；"精力"随发言消耗、随时间恢复。
  - 关键启发：**像人首先是不抢话**。我们已经有 `NOT_PRESENT / FAMILIAR`，但没有"精力"和"等待补充消息"的节奏。
- Angel Memory（记忆与认知）：https://github.com/kawayiYokami/astrbot_plugin_angel_memory
  - 记住人、分开记、主动铭记/回忆、灵魂状态（四对情绪刻度）、每天睡眠整理。
  - 关键启发：**情绪应该是一个缓慢变化的连续量**，而不是每轮重新决定"我现在该冷淡还是热情"。
- Angel Smile（表情包）：https://github.com/kawayiYokami/astrbot_plugin_angel_smile
  - 表情包管理；看到合适的就收。
  - 关键启发：表情不是"配图"，是**语气的一部分**；应该按情绪桶挑，而不是按关键词硬匹配。

> 许可：AGPL / GPL 系列，只借鉴思路。

### 3.4 dsh-fish-tone——"人味"可以是一层确定性的后处理

仓库：https://github.com/MX3a48c5/dsh-fish-tone

它把"像人说话"和"性格"拆成两个包：主包只做语气微调（犹豫半秒、句尾小尾巴、无用度统计），性格包单独装。方法来自 B 站 10 万条评论/弹幕的语料统计，报告里的关键数字：

- 81.3% 的句子没有结尾标点；
- 语病密度只有 1.65/千字。

我们的 `expression/tone.py` 正是受它启发，但目前只做了"去句号 + 少量语气词"，没有做"犹豫、重复、自我打断、错别字"这些更接近真人的噪声。

> 许可：MIT，可安全借鉴规则。

### 3.5 Generative Agents——记忆、反思、计划

论文：https://arxiv.org/abs/2304.03442

Stanford 的生成式智能体架构：完整记录经历 → 定期反思成更高层印象 → 按当前情境动态检索 → 用检索结果指导计划。消融实验证明 observation / planning / reflection 三者都直接影响"可信度"。

对应到蓝晴：我们的 `memory.py` 有摘要、印象、主动记忆，但**反思（把多件事合成一句"她最近怎么样"）和计划（今天想做什么）是缺的**。所以她说的话没有"连续性"，今天和昨天可以完全无关。

### 3.6 补充：为什么"禁止 AI 味"的清单常常失效

- 负向指令需要模型先想象"错误答案"再避开，会占用注意力，且容易过度泛化（例如为了不"说教"，索性只说 `？`）。
- 更有效的做法是**给正面样本 + 少量硬边界**：10~20 条真实语料，比 30 条"不许"更能定住语感。
- 这也是 MaiBot 把 `reply_style` 写成一句风格描述、把语感交给"表达学习"的原因。

## 4. 对照表：蓝晴 vs 参考项目

| 维度 | 蓝晴现状 | 参考做法 | 差距 |
|---|---|---|---|
| 人设长度 | system ≈ 4k 字 + 通用规则 1k+ | MaiBot 三段各 1~2 句 | 过长，规则互相稀释 |
| 人设定向 | 大量"不许/别说" | 正面 `reply_style` + 真实语料 | 负向过载 |
| 语料来源 | 作者编写的示例 | 本群真实消息（MaiBot 表达学习 / 牛牛复读） | 语感不属于这个群 |
| 发言时机 | 状态机 + 8% 随机 | 频率值 + 防抖 + 退避 + 精力 | 缺少"等一等"和"累了" |
| 回复形态 | 96% 单气泡、21% ≤2 字 | 回复分割、多风格概率、错别字 | 形态单一 |
| 具体性 | 很少提具体人/事/旧梗 | 记忆检索 + 印象 + 反思 | 记忆没用进句子 |
| 情绪 | 每轮即时判断 | 连续情绪刻度（Angel Memory） | 无连续性 |
| 表情 | 关键词/自动补图 | 情绪桶 + 收藏 + 使用记录 | 偏"配图"而非"语气" |
| 决策与生成 | 一个 agent 全包 | Planner / Replyer 分离 | 没有"先想说什么方向" |
| 评估 | 靠肉眼 | 语料统计 + 人工打分 | 没有基线 |

## 5. 改造方向（建议顺序，不含实现）

### A. 人设减重（最高优先级）

目标：system 从 ~4k 字压到 **1.2~1.8k 字**。

- 只保留三块：
  1. **她是谁**（身份、住哪、在干嘛、和谁熟）——5~8 行；
  2. **她怎么参与**（什么时候说、什么时候不说、一次说几条）——5~8 行；
  3. **她怎么说话**（长度、标点、口头禅、错字、表情频率）——5~8 行。
- 删除所有"失败示例"和大部分"不许"；把边界收敛成 5 条以内。
- 把"反 AI 味"清单移到通用规则里，保持一份，不要人设里再抄一遍。
- 保留身份资产：好感度、关系标签、群白名单、管理命令不动。

预期：模型不再把注意力花在"别踩雷"，`？` 率应明显下降。

### B. 语料驱动（决定"像不像这个群"）

- 从群消息存档里挑 **200~500 条**真实发言，按场景分桶：接梗、被夸、被骂、安慰、求助、闲聊、晚安。
- 每条只保留"发言人 → 原话"，作为 few-shot 或检索样本；**不要改写**。
- 按当前上下文检索 3~5 条最接近的样本注入，而不是每轮全量塞。
- 同时整理本群的高频称呼、黑话、梗（不需要模型生成，直接从语料统计）。
- 这一步是把"作者想象中的蓝晴"换成"这个群里的蓝晴"。

### C. 回复形态（立刻能感知到的"人味"）

- 目标分布（可按群微调）：
  - 单气泡 60~70%，双气泡 25~30%，三气泡 5%；
  - ≤6 字 50%，7~15 字 35%，>15 字 15%；
  - `？` 单独成句不超过 5%；
  - 表情约每 3~5 轮一张，按情绪桶挑。
- 关键是**允许她"多说一句"**：现在的人设反复强调"能一个字就一个字"，把多气泡的路堵死了。

### D. 记忆具体性（解决"换个人名也成立"）

- 每轮回复前，除了"相关记忆"，额外给一条**具体锚点**：最近一次和当前说话人发生的事、群里的一个旧梗、她今天的状态。
- 回复后做一次轻量检查：这句话是否只对当前语境成立？如果完全可替换，降低采样或要求重说（可作为离线评估指标，不一定上线）。
- **不要虚构"此刻状态"**（2026-11-08 修正）：任何固定的"我在干嘛"输入，时间一长都会因为反复出现而露馅；频率控制只是拖延。
- 个人状态的唯一来源改成**真实聊天记录**：`_recent_anchor`（和这个人的上次）、用户印象、长期记忆，以及上下文里的真实历史。
- 被问到"你在干嘛"时，让模型基于这些真实记录回答；没有记录就不编，允许说"没干嘛/在想吃什么"这种不承载事实的随口话。

### E. 时机与节奏（减少"应答机"感）

- 被动触发也加 **1~4 秒阅读延迟**（按消息长度和当前活跃度），不要 0 秒回复。
- 引入 MaiBot 式的**防抖**：同一人连续发消息时等 1.5~2 秒；换人时 0.5 秒；被 @ 才立即。
- 给"随机触发"加**退避**：连续 N 次选择不回，下次检查间隔递增。
- 可选：给蓝晴一个"精力"值，长回复消耗更多，精力低时更少接话（Angel Heart 的做法）。

### F. 评估（否则改完还是拍脑袋）

建一个 50~100 条的离线评测集：真实群聊上下文 + 蓝晴的回复。

- 人工 1~5 分："这句话像不像这个群的人说的"；
- 自动指标：`？` 率、平均字数、多气泡率、是否提到具体人/事、重复率、每轮工具调用数；
- A/B：旧人设 vs 新人设，同一批上下文各生成一次，盲评。

没有这组基线，"更像人"永远无法验证。

## 6. 优先级与预期收益

| 优先级 | 动作 | 预期收益 | 成本 |
|---|---|---|---|
| P0 | 人设减重（A） | 直接降低"规则味/客服味" | 低（只改 prompt） |
| P0 | 回复形态（C） | 立刻可感知的节奏变化 | 低（prompt + 少量后处理） |
| P1 | 语料库（B） | 语感从"编的"变成"群里的" | 中（需要清洗语料） |
| P1 | 时机与节奏（E） | 减少应答机感 | 中（改动消息处理链路） |
| P2 | 记忆具体性（D） | 解决"每句都可替换" | 中高（检索 + 注入） |
| P2 | 评估基线（F） | 让后续改动可验证 | 中（需要人工标注） |

## 8. 明确不做的事

- 不继续往人设里加"不许"；
- 不引入 Tantivy / 向量库 / 重排，直到语料和评估跑通；
- 不恢复冷场主动发言（已于 2026-11-07 删除）；
- 不把 Angel 三件套整仓搬进来；
- 不在没有评测基线的情况下大改采样参数。

| A 人设减重 | 已做（修正） | `plugins/FakeAi/prompts/lanqing_agent.yml`：system 压到 ~1.1k；只留身份、关系、参与、说话、7 条语感示例和 3 行工具说明；**不保留生活流水账** |
| B 语料驱动 | 已做 | `plugins/FakeAi/style_corpus.py` + `scripts/build_fakeai_style_corpus.py`；生成 `data/FakeAi/style_corpus.json`（当前 500 条），每轮按话题挑 4 条注入 |
| C 回复形态 | 已做（修正） | `_shape_reply`：连续「？」自动换说法；长句 30% 拆两条；不做重复末字（会把「行吧」变「行吧吧」） |
| D 记忆具体性 | 已做（修正） | 不注入虚构的「此刻状态」；只用真实聊天记录：`_recent_anchor` 注入「和这个人的上次」，印象/长期记忆照旧 |
| E 时机与节奏 | 已做 | `_reading_delay`：主动 0.6~1.6s、被动 1.2~3.2s，同人续发再加 0.8~1.6s；随机触发连续沉默后 15s→300s 退避 |

| G 闲聊直出 | 已做 | 参考 MaiBot Replyer：普通聊天不经过 20+ 工具循环，直接用「人设 + 聊天记录 + 语感样本 + 相关记忆」生成 1~2 条；插件/识图请求仍走 agent（`direct_chat_enabled`） |
| H 表情补充 | 已做 | 自动补图先按回复情绪桶选，再退回随机；不再用整段上下文当 topic |
| I 回复策划 | 已做 | 直出前一次短调用，输出「接什么情绪/提不提旧事/玩不玩梗/表情桶」；结果注入 Replyer，并驱动补图（`planner_enabled`） |

**刻意没做**

- 不自动改错别字，也不重复末字：实测会产生「行行」「用用」，一眼假；只保留拆句和问号替换。
- 不做精力值：需要和发言预算、状态机一起调，等 A~C 的盲评结果再定。
- 不做 Planner/Replyer 双调用：当前一轮一次调用，先看人设与语料的效果，避免成本和延迟翻倍。
- 不改采样参数：没有 A/B 基线前不动 temperature/top_p。

**怎么验证**

1. 重启 FakeAi，正常聊 2~3 天；
2. `python scripts/eval_fakeai_persona.py --compare data/FakeAi/eval/baseline_20261108.json`
3. 重点看：`short_question_rate`（目标 < 5%）、`multi_bubble_rate`（目标 25~35%）、`avg_chars`（目标 8~12）；
4. `--export-csv` 导出 60 条做人工盲评，1~5 分。

## 10. B站/贴吧评论语料可行性（2026-11-08）

### 10.1 已经有人这么做，但用法分两种

| 项目 | 语料 | 用法 | 结论 |
|---|---|---|---|
| [dsh-fish-tone](https://github.com/MX3a48c5/dsh-fish-tone) | B站 100,097 条评论（338.5 万字）+ 1,026,257 条弹幕（851.9 万字），528/279 个视频 | **只做统计校准**，不把评论喂给模型 | 量出真人语病 1.65/千字、句末标点、句式密度，用来定语气规则 |
| [bilibili_comments_crawl](https://github.com/FunnySaltyFish/bilibili_comments_crawl) | 评论区树状对话链 | 爬取后转成对话数据集，用于 Aquila 微调 | 需要登录 Cookie；作者明确写了合规风险 |
| [CDial-GPT / LCCC](https://github.com/thu-coai/CDial-GPT) | 700 万+ 轮中文短对话，含 232 万轮贴吧语料 + 微博/豆瓣/字幕 | 预训练 / 微调 | MIT 许可，适合离线研究，不适合直接当聊天样本 |
| [MaiBot](https://docs.maibot.chat/manual/configuration/bot-config) / [Pallas-Bot](https://github.com/PallasBot/Pallas-Bot) | 本群聊天记录 | 学表达、学黑话、复读 | 没有用公共评论区，因为"像这个群"比"像互联网"更重要 |

dsh 的统计里有一个很关键的结论：**真人的"人味"主要体现在微文本层**——标点、句长、错字、语气词、句式是否扎堆，而不是内容多有趣。它量出来的几个倍数：

- "不是 X 而是 Y"：真人 0.06/千字，AI 评论 0.57/千字（9 倍）
- "最…的是"：0.05 vs 1.86（37 倍）
- "先…再…"：0.01 vs 0.41（41 倍）
- 破折号：0.22 vs 3.43（16 倍）

这说明：**评论语料最有价值的是"统计尺子"，不是"句子库"。**

### 10.2 可行性评估

| 维度 | B站/贴吧评论 | 本群聊天记录 |
|---|---|---|
| 语言相关性 | 公开评论区是**表演型**语言：抬杠、玩梗、抢热评 | 群聊是**熟人型**语言：接话、敷衍、内部梗 |
| 噪声 | 广告、攻击、NSFW、地域黑、复读、抽奖、机器人 | 也有，但规模小、可人工确认 |
| 合规 | 平台条款通常禁止爬取；用户内容有版权；需匿名化 | 自己群的记录，风险低 |
| 时效 | 网络梗过期快，2020 年语料现在看很旧 | 跟群同步 |
| 成本 | 爬取、清洗、去重、审核、持续更新 | 已有 2.2 万条存档 |
| 收益 | 提升标点/句长/错字/句式等**微文本** | 提升"这个群的关系、称呼、梗" |
| 风险 | 学成"评论区人格"：爱抬杠、句句玩梗、攻击性强 | 样本少时容易过拟合几个人的口癖 |

### 10.3 结论

**可以，但不建议把评论原样作为 few-shot 注入。**

直接用评论区语料，蓝晴会变得像"热评区"，而不是"群里的蓝晴"：句子短、攻击性强、每句都想抖机灵，这和她现在"懒得说话"的设定也冲突。

更稳的做法是两层：

1. **统计校准（推荐，低风险）**
   用公开评论语料（优先 LCCC 这类有许可的数据集，而不是现爬 B站/贴吧）量出：句末标点率、平均句长、错字密度、语气词密度、句式扎堆率。把这些数字用来校准 `tone.py`、`_shape_reply` 的阈值。**只保留聚合统计，不保留原文。**
2. **黑话/梗词典（可选）**
   只提取"词条 + 释义 + 使用场景"，用于理解群友在说什么，不用于模仿句式。比如"典 / 急 / 破防 / 含金量"这类词，给一份小词典就够，不需要整段评论。

**本群语料仍然是第一优先级。** 蓝晴要像的是"这个群的人"，不是"互联网评论区的人"。只有当本群语料明显不够（比如新群、冷群）时，才考虑用 LCCC 的短对话子集做补充，而且同样只做统计或极少量人工精选样本。

### 10.4 合规红线

- 不写运行时爬虫，不把 B站/贴吧抓取接进 Bot；
- 不提交、不分发原始评论；
- 如做离线统计，只用公开 API、低频、匿名化，且只保留聚合数字；
- 优先使用 MIT / Apache 等明确许可的数据集（LCCC 为 MIT）；
- 评论里的用户名、头像、链接、个人信息一律不进入任何文件。

### 10.5 本群语料的落地路径（已做）

1. `scripts/analyze_tone_stats.py`：直接读 `data/db/memory.db` 的群消息和 `data/FakeAi/traces` 的蓝晴回复，输出对比指标；
2. 用输出的数字校准规则（句长、问号窗口、打字毛刺），不新增样本注入；
3. 本群 `style_corpus.json`（`scripts/build_fakeai_style_corpus.py` 生成）继续作为唯一的 few-shot 来源；
4. 清除命令、插件输出、`[引用消息]`、`[sysmsg]` 等噪声后再统计——这些会显著抬高"群友"的句长和句式密度。
5. 如果以后要扩样本，优先从本群历史里扩，而不是从公共评论区扩。

### 10.6 用本群语料跑出来的结果（2026-11-08）

没有用 B站/贴吧，直接拿 `data/db/memory.db` 的群消息做语料，脚本：
`scripts/analyze_tone_stats.py`。对比对象是蓝晴的留档回复。

| 指标 | 群友 | 蓝晴 | 判断 |
|---|---:|---:|---|
| 消息数 | 12,737 | 804 | 已剔除命令/插件输出/引用消息 |
| 平均字数 | 10.31 | 7.46 | 蓝晴明显偏短 |
| 中位字数 | 7 | 6 | |
| ≤6 字占比 | 44.6% | 54.4% | 短回复过多 |
| >15 字占比 | 15.0% | 5.2% | 几乎不说长句 |
| 句末无标点率 | 93.7% | 80.6% | 蓝晴标点偏多 |
| 问号结尾率 | 2.1% | **18.3%** | 最大的伪人信号 |
| 语气词结尾率 | 6.2% | 5.5% | 接近，不用动 |
| 重复字/千字 | 7.3 | 4.3 | 蓝晴偏"干净" |
| 感觉/可能/好像（每千字） | 0.98 / 0.56 / 0.50 | 0 / 0 / 0.17 | 缺少不确定语气 |

据此做了三项校准：

1. 人设句长从"1~10 字"改成"3~15 字，多数 5~10；有话说 15~25 字也可以"；
2. `_shape_reply` 的问号窗口从最近 12 条扩到 20 条，纯问号上限压到 5% 以内；
3. 打字毛刺率从 3% 提到 5%，接近群友的重复字密度。

语气词结尾率已经接近，不再加"吧/呢/啊"；句式类指标群友本身就很低（0.02~0.05/千字），不需要刻意模仿。
